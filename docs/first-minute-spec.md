> 作者：主策划（整合喜剧导演 / 美术 / 新手引导三份方案）
> 适用：`game/` 网页原型。纯 HTML/CSS/原生 ES modules，零依赖，手机浏览器可跑，美术只用 SVG/CSS 画，字体只用 Google Fonts，并给系统字体兜底。

## 0. 主策划裁决总表（冲突处一律按此执行）

| # | 冲突点 | 三方意见 | 裁决 | 理由 |
|---|---|---|---|---|
| R1 | 三个键的颜色 | 喜剧/UX：滚红、闭嘴紫、收金；美术：收绿、滚灰牌 | **滚 `#E8402F` 红，闭嘴 `#6A4EE8` 紫，收 `#FFC21A` 金。牌子颜色 = 按键颜色。** 废除“灰=滚”，绿色只留给翡翠柠檬饮料本身 | 玩家只需记一条规则：“牌子什么色就按什么色键”。灰色按键看起来像不能按；250 本来就是金色，和钱、号码牌对得上 |

## 1. 目标与验收标准

### 1.1 目标（一句话）

新玩家点一下“开店”后，**60 秒内看懂规则、亲手打完原片全流程、在“调你妈”那一拍笑出来**，然后不看任何说明进入自由营业。

### 1.2 自动化验收（Playwright 和 node:test，必须全部通过）

| ID | 内容 | 判定方法 | 通过标准 |
|---|---|---|---|
| A1 | 首题速度 | 从点“开店”到第一张点单牌 `.sign[data-state=up]` 出现 | ≤ 3.5s（目标 3.0s） |
| A2 | 剧本无计时 | 剧本期间每 100ms 读 `game.state.phase` | 全程是 `'idle'`；DOM 中没有 `.sign-timer` |
| A3 | 笑点不被吃掉 | 从按下 W4（闭嘴）到第一位自由营业顾客可以按键 | ≥ 8000ms；其中“调你妈”爆点开始后 1800ms 内，三个按键都处于 `inputLocked` |
| A4 | 乱按也能走完 | 从开店起每 300ms 随机按一个键 | 第 1 天在 120s 内出现打烊卡；每次按错 300ms 内出现吐槽字幕；同一拍第二次按错时自动推进 |
| A5 | 最慢路线 | 每个等待点都等到超时，超时演出结束、手指出现后 1000ms 再按正确键（超时只触发一次，之后剧本停在手指提示等玩家，不会自动推进） | 从开店到 F4 ≤ 70s |
| A6 | 说完才计时 | 普通营业中，顾客 `arrive` 到 `ready` 事件之间 | `state.current.patienceMs` 保持不变 |
| A7 | 落地停顿 | 普通营业里，按对后到下一个 `arrive` 的间隔 | ≥ 当天的 L（第 1 天 650ms，大爆点 1100ms） |
| A8 | 首日不过载 | 第 1 天全程 | `.bar-aura`、`.bar-fury` 是 `display:none`；连击数在连击 < 5 时不可见 |
| A9 | 小屏可读 | 360×640 视口 | 所有文字 ≥ 12px；牌子主文字 ≥ 36px；按键可见尺寸 ≥ 96×88px |
| A10 | 花字不压牌 | 剧本和第 1 天自由营业中，每 100ms 采样一次 | `.hz` 外框和 `.sign` 外框（各外扩 2cqw）的交集面积 = 0 |
| A11 | 不用 emoji | 扫描 `ui.js`、`art.js`、`style.css` 和渲染后的 DOM | 没有 Unicode emoji（`\p{Extended_Pictographic}`），只有 SVG 和文字 |
| A12 | 内容检查 | `node tools/check-content.mjs` | 全部通过，包括新增的 H1–H4 项（见 8.7） |
| A13 | 性能 | Chromium 模拟 4× CPU 降速，360×640，剧本全程 | 掉帧（>32ms 的帧）≤ 5%；同屏 SVG 节点 ≤ 400 |

### 1.3 真人测试验收（10 位没玩过的测试者，手机竖屏，开声音）

| ID | 内容 | 通过标准 |
|---|---|---|
| U1 | 新键靠高亮一次就会 | ≥ 8/10 在第一位顾客的牌子举好后 5s 内按下“滚”，而且中间不问问题 |
| U2 | 旧键不靠高亮也会 | ≥ 7/10 在第二位顾客（15 杯）的高亮出现之前（1200ms 内）按下“滚” |
| U3 | 规则可以迁移 | 第 1 天自由营业的前三位固定顾客（“1杯”滚、“100杯”收、“可以少冰吗？”闭嘴），≥ 8/10 三位都在 2s 内按对 |
| U4 | 听得懂笑话 | 第 1 天结束后，≥ 8/10 能用一句话复述笑点（“点 250 杯被收单、两个月后才拿得到”，或“越骂人越多”） |
| U5 | 眼前一亮 | 现场观察，≥ 7/10 在“调你妈”那一拍笑出声或明显笑了 |
| U6 | 想继续 | 第 1 天打烊卡出现后，≥ 8/10 主动点进第 2 天 |

## 2. 美术规范

### 2.1 方向

“台湾夜市手写招牌 × 热血漫画仰角怒吼格 × 综艺字卡”。粗黑描边，平涂加一层阴影，光从头顶打下来。镜头站在顾客的位置往上拍，店员居高临下。

硬规则：
- 禁止 emoji，禁止外部图片，禁止 SVG `<filter>`、`filter: drop-shadow`、`blur`、`backdrop-filter`。阴影一律用偏移的同形状色块来画。
- 每个填色只配一个阴影色，算法统一为 `color-mix(in srgb, 原色 78%, #1B1311)`。阴影只画在“朝下的面”（下巴底、帽檐底、柜台檐口底、鼻孔），靠这一点看出仰角。
- 统一 `stroke-linejoin: round; stroke-linecap: round`。

### 2.4 字体

`index.html` 的 `<head>`：

```html
<link rel="preconnect" href="https://fonts.googleapis.com">
<link rel="preconnect" href="https://fonts.gstatic.com" crossorigin>
<link rel="stylesheet" href="https://fonts.googleapis.com/css2?family=Noto+Sans+TC:wght@700;900&family=Noto+Sans+SC:wght@700;900&family=LXGW+WenKai+TC:wght@700&family=Bangers&display=swap">
```

```css
:root{
  --font-zh:"Noto Sans TC","Noto Sans SC","PingFang TC","PingFang SC","Microsoft JhengHei","Heiti TC","Noto Sans CJK TC",sans-serif;
  --font-sign:"LXGW WenKai TC","Kaiti TC","STKaiti","BiauKai","DFKai-SB",var(--font-zh);
  --font-en:"Bangers","Impact","Arial Black",sans-serif;
}
```

- Google 对 CJK 字体按 unicode-range 切片加载，首屏只拉用到的字。**不用 `text=` 子集**，因为牌子上的字来自内容表，是动态的。
- 简体内容里 TC 字体缺的字，会按字形逐字回退到 Noto Sans SC。WenKai TC 缺的字回退到楷体，再不行用黑体。都能接受。
- 加载策略：开始页出现时调用 `document.fonts.load('900 1em "Noto Sans TC"', '滚闭嘴收调你妈250')` 和 `document.fonts.load('700 1em "LXGW WenKai TC"', '嗯杯少甜冰')`。玩家点“开店”时，如果还没加载完，最多再等 300ms，然后直接用兜底字体开始。
- 用途：花字、按键、HUD 数字用 Noto Sans 900；字幕用 700；点单牌手写字和 S4 心声用 WenKai；英文版花字和按键用 Bangers，英文字幕正文用 `system-ui`。

### 2.5 描边粗细（越近越粗）

| 对象 | 渲染后 | viewBox 里的 stroke-width |
|---|---|---|
| 顾客 | 1.2cqw | 顾客 SVG 宽 34cqw / 200 单位 → `7` |
| 店员主轮廓 | 1.1cqw | 店员 SVG 宽 60cqw / 240 单位 → `4.5` |
| 角色内部线 | 0.7cqw | 店员 `3`，顾客 `4` |
| 背景 | 0.45cqw | 背景 360 单位 → `1.6` |

### 2.6 店员 SVG：5 种表情图层

结构：每种表情是一整组 `g.m-*`，每种手臂姿势是一组 `g.a-*`，CSS 按 `data-mood` 只显示其中一组。现有 `ui.js` 的 mood 名（`idle / hit / perfect / polite / rage / over`）原样保留，状态机不用改。

新增两个**叠加 class**，用于剧本里的细腻表演（不算新表情）：
- `.squint`：铺垫时眯眼。`m-idle` 的眼白组 `scaleY(.45)`，`transform-origin` 设在眼睛中线 y=95。
- `.crack`：笑容裂开。在 `m-polite` 上叠一条 `path.crack`（`stroke-dasharray` 从 0 画到全长，100ms）。

代码放进 `src/art.js`，导出 `CLERK_SVG` 字符串：

```html
<svg class="clerk" viewBox="0 0 240 300" overflow="visible" data-mood="idle" aria-hidden="true">
<g class="c-all" stroke="#1B1311" stroke-width="4.5" stroke-linejoin="round" stroke-linecap="round">
  <g class="c-body">
    <path fill="#2F2557" d="M36 300 L60 178 Q120 152 180 178 L204 300 Z"/>
```

### 2.11 镜头系统

- 结构：`.stage > .shaker > .cam > (.shop, .clerk, .counter, .cust-wrap, .sign)`。HUD、花字层 `.hz-layer`、字幕带、按键都在 `.cam` **外面**，不跟着缩放。
- 实现：`.cam{transform-origin:0 0}`。对焦点 F=(fx%, fy%)、缩放 s，设 `transform: translate(calc(var(--fx) * (1 - s)), calc(var(--fy) * (1 - s))) scale(s)`；JS 里先把 F 换算成 px 再写入。这样 F 点在屏幕上位置不动；在两个对焦点之间插值就是平移，不会跳。
- 过渡用 `transition: transform <dur> <ease>`，ease 默认 `cubic-bezier(.2,.8,.2,1)`；快推（≤120ms）用 `cubic-bezier(.5,0,.2,1)`。
- 命名对焦点：`FACE (50,20)`、`MOUTH (50,24)`、`SIGN (30,55)`、`CUST (29,67)`、`GOLDSIGN (72,11.5)`、`WIDE (50,40)`。
- 震屏沿用现有 `.shaker` 的 `shake-0..3`，振幅改成 px：3 / 6 / 10 / 14px。白闪：`.flash` 白色全屏层，透明度 0→.85→0，共 40ms。
- `prefers-reduced-motion: reduce` 时：镜头缩放上限 1.10，震屏振幅减半，白闪关闭。

### 3.1 通用约定

- 剧本由 `src/opening.js` 驱动，**引擎全程 `idle`**。时间分两类：A 段从玩家点“开店”算起的绝对时间；W1–W4 是“顾客说完、开始等玩家”的时刻，P1–P4 是玩家按对键的时刻，之后的时间写相对值。
- 花字样式 S1–S5 见第 5 节。声音名称见 8.5 的 SFX 清单。
- 语音片段：台词里的 `|` 是切点，前半是“铺垫段”，后半是“爆点段”，分成两个 clip。下文写的时长是**目标值**，实际以语音包里的 clip 长度为准，后续节拍顺延（时间轴用“上一段结束 + 间隔”串起来，不写死绝对时间）。
- 背景声床（bed）= 夜市人声 + 110 BPM 合成小节奏，-18dB。“静音”指 bed 在 30ms 内压到 -60dB。

**等待点的逐级提示**（剧本里没有计时条，用提示代替）：

| 等待点之后 | 新键（W1 滚、W3 收、W4 闭嘴） | 旧键（W2 滚） |
|---|---|---|
| +0 | 只有正确键亮：另外两个键透明度 0.35，**仍然可以按**；正确键呼吸动画 scale 1→1.06，周期 600ms | 三个键都正常，不亮 |
| +900 / +1200 | 店员手指敲柜台 3 下（`tap` 音效，间隔 120ms） | +1200：正确键开始呼吸 |
| +1500 / +2000 | SVG 漫画手指从右下伸进来点正确键（400ms 一循环）；从牌子到键画一条同色虚线（宽 0.8cqw，虚线 2cqw/1.5cqw，流动 600ms 一循环） | +2000：手指和虚线出现 |
| +5000 | 超时：服务腔演出（见各段），然后回到同一位顾客，手指立即出现，**之后不再超时** | 同左 |

**按错**（R3）：
- 第一次按错 → 300ms 内播放该拍的吐槽台词（店员 `idle + .squint`，字幕 + S3 花字显示吐槽），顾客不动；吐槽结束时正确键立刻亮起，手指和虚线同时出现。
- 第二次按错（同一拍）→ 店员说“算了，我自己来。”（约 900ms），然后按“玩家按对了正确键”继续，P = 这句结束的时刻。
- 按错永远不扣分、不减排队。
- 吐槽和“算了”播放期间按键锁定（`inputLocked`），避免连按刷屏。

**跳过**：剧本完整走完一次后（`localStorage['250cups.openingDone']='1'`），以后再进入时，右上角 1200ms 后出现“跳过 ▸”（5cqw，`--cream` 字，`#0008` 底）。点击后直接进入 F3。首次游玩不提供跳过。

## 4. 普通营业节奏与难度曲线

### 4.1 每位顾客的时间线（引擎和 main 共同实现）

| 步骤 | 规则 |
|---|---|
| 1 入场 | 头弹出（时长见 4.2 的“入场”列），引擎发 `arrive`，`current.speaking = true` |
| 2 举牌 | 入场后 120ms 开始举牌，翻牌 160ms → **signUp = 入场 + 280ms** |

## 5. 花字系统

### 5.1 渲染

- `.hz-layer`：盖在舞台上（`position:absolute; inset:0 0 26% 0; pointer-events:none; z-index:20`），在 `.cam` 外面。
- 每个花字是一个 `<svg class="hz" viewBox="0 0 100 H">`（H = 舞台高宽比 × 100，9:16 时为 177.8），宽 100% 舞台，所以 **1 个 viewBox 单位 = 1cqw**。
- 每个花字画两层 `<text>`，都设 `paint-order="stroke" stroke-linejoin="round" text-anchor="middle"`：
  1. 外层：`stroke = 外描边色`，`stroke-width = 外描边值`，`fill = 外描边色`
  2. 内层：`stroke = 内描边色`，`stroke-width = 内描边值`，`fill = 填色`（S2 用 `url(#hzGold)` 渐变）
- 渐变 `<linearGradient id="hzGold" x1="0" y1="0" x2="0" y2="1">`：`#FFF6C2` 0% → `#FFD23F` 45% → `#F29A00` 100%，放在 `.hz-layer` 里一个隐藏的 `<svg><defs>` 中。
- 放射速度线、光芒都是 SVG `<polygon>` 或 CSS `conic-gradient`，不用滤镜。

### 5.3 自动挑花字（`src/huazi.js`，纯函数，可单测）

`pickHuazi(line, ctx) → [{ text, style, seg: 'setup'|'punch', ratio }]`

处理对象是店员台词去掉舞台指示后的文本（`stripStage`），`|` 前是 setup 段，后是 punch 段；没有 `|` 时整句都是 punch 段。按分数从高到低逐条匹配：

| 分数 | 规则（正则） | 样式 | 显示文字 |
|---|---|---|---|
| 100 | `/([一-龥])你妈/` | S1 | 匹配到的“X你妈！” |
| 90 | `/250|二百五|251|520/` | S2 | 匹配到的数字，后面紧跟“杯”就带上“杯” |
| 80 | 段尾 `/(滚|闭嘴|收)[！!。]?$/`（英文：`/(scram|shut it|deal|get out)[!.]?$/i`） | 滚、闭嘴用 S1；收用 S2 | “滚！”“闭嘴！”“收！” |
| 75 | `/黄金比例/` | S2 | 有“最好喝”就是“黄金比例最好喝”，否则“黄金比例” |
| 70 | `/两个月/` | 普通营业用 S2 小号；剧本和取餐日用 S5 | “两个月后” |
| 50 | setup 段 ≤5 字且以 `？` 结尾（如“还在想？”“15杯？”） | S3 | 原文 |
| 40 | 前面都没命中时，取 punch 段最后一个分句（≤6 字） | S3 | 原文 |

- `ratio` = 关键词首字符在该段（去掉舞台指示后）中的位置 ÷ 段长。花字出现时间 = 该段 clip 开始时间 + clip 时长 × ratio。S3 在 setup 段开始时出现；S4 在顾客反应动作开始时出现。

**限流**（`ctx` 里带最近记录）：
1. 一句台词最多 2 个花字：1 个 S3 铺垫加 1 个 S1 或 S2 爆点。
2. 普通营业中，每 3 位顾客最多 1 个 S1。蓄力 2 段、复仇骂、爆气不受此限。超出的 S1 降级为“字幕强调”：字幕里那几个字变 `--hz-yellow`、字号 ×1.3，没有动效。
3. 同一个关键词在 5 位顾客之内不重复出花字。
4. 两个花字至少间隔 450ms。
5. 显示文字超过 7 字时，只截取匹配到的那一段。

**手工覆盖**：`content.*.js` 的顾客条目可选字段 `hua: [['太少', 3], ['滚！', 1]]`（数字是样式编号 1–5）。有它就跳过自动规则。检查项见 8.7 的 H2。

### 8.1 `src/engine.js`（负责人：开发 A）

1. `DEFAULT_CONFIG` 新增：`speakMaxMs: 1880`、`minAnswerMs: 280`、`windowStartMs: 2400`、`windowEndMs: 2400`、`introBonusMs: 300`、`comboTightenAt: 30`、`comboTightenMs: 100`、`windowFloorMs: 1000`、`landMs: 650`、`landBigMs: 1100`、`landWrongMs: 550`、`landPoliteMs: 1600`、`timeoutCostsAura: true`、`furyEnabled: true`。`patienceStartMs` / `patienceEndMs` / `introPatienceMs` / `gapMs` 改为这套新参数，旧键名保留为别名一个版本（读到旧键名时映射过去），避免现有测试一次全挂。**`auraWrong: 0` 不动。**
2. `patienceFor(elapsedMs, combo)`：`W = windowStart + (windowEnd − windowStart) × (elapsed / duration)`；`elapsed < introMs` 时加 `introBonusMs`；`combo ≥ comboTightenAt` 时减 `comboTightenMs`；结果不低于 `windowFloorMs`。
3. `spawn()`：`s.current = { customer, speaking: true, speakLeftMs: cfg.speakMaxMs, sinceArriveMs: 0, step: 0, patienceMs: W, patienceMaxMs: W }`。
4. 新方法 `speechDone()`：若 `current.speaking`，设为 false，emit `ready`（payload `{ customer, patienceMs }`）。
5. `tick()`：有 `current` 时先加 `sinceArriveMs`；`speaking` 时只减 `speakLeftMs`，到 0 就调用 `speechDone()`；**`speaking` 期间不减 `patienceMs`**。
6. `press()`：`sinceArriveMs < minAnswerMs` 时返回 null。`speaking` 时按下算抢话：`reactionMs = 0`，`perfect = correct`，payload 加 `cutIn: true`。
7. 落地：按完后 `scheduleNext(kind)`，kind 为 `normal / big / wrong / polite`，对应 `gapLeftMs = landMs / landBigMs / landWrongMs / landPoliteMs`。big 的判定见 4.1。`charge()` 升到 2 段时，`gapLeftMs = max(gapLeftMs, landBigMs − 已过时间)`。
8. 新方法 `delayNext(ms)`：`current` 为空时 `gapLeftMs = max(gapLeftMs, ms)`，供 main 按语音实际长度延后下一位。
9. 超时：`timeoutCostsAura === false` 时不扣气势（第 1 天）。`furyEnabled === false` 时 `addFury` 不生效（第 1–2 天）。
10. 双步顾客：`customer.steps` 存在时，第 `step` 步的正确键是 `steps[step]`。第一步按对时 emit `step`（payload `{ customer, step: 1, key }`），`current` 保留，`speaking = true` 并重置 `speakLeftMs` 和窗口，等第二步；最后一步再走正常 `resolve`。

### 8.5 `src/audio.js`（负责人：开发 D）
